# DESIGN-note：分享页在 X 上显示信息密集型大图卡片

## 目标

把 `/view/{view_token}` 分享链接贴到 X 时，显示一张 1200×630 的大图卡片：大模型写的吸睛标题、最多 3 条要点、平台和作者、品牌域名。读者扫一眼就知道这期内容讲什么。

## 非目标

- 不显示视频封面：封面地址目前没有任何平台落盘（research.md 第 3 节），这次不补封面持久化。
- 不改总结正文（`llm_summary.txt`）的 prompt、格式和篇幅预算。
- 不做多套模板或主题切换，只做一个版式。
- 不在这一批里补全历史任务；回填脚本另开一张卡，等新任务效果确认后再派。
- 不处理 `?page=` 纯 HTML 导出页（views.py:405 一带），只处理主分享页。

## 为什么不是分区 / 删除 / 约定

- **分区**：卡片文案单独存成 `llm_share_card.json`，图片单独存成 `og_card.png`，都放在任务缓存目录里，各写各的文件。这样不和 `llm_summary.txt` 抢同一个文件，也不需要新建数据库表。
- **删除**：砍掉封面图层，也砍掉「抓图请求进来时才现调大模型」这条路，所以请求路径里没有大模型调用和超时问题。还砍掉了历史任务的降级卡：没有卡片文案的任务，页面就不输出 `og:image`，保持现在的行为，也就没有降级分支。
- **约定**：图片地址带版本号 `?v=<llm_share_card.json 的修改时间>`。重新总结后地址自动变化，X 的缓存（约 7 天）不会一直显示旧图。不需要额外的失效机制。

## 方案要点与已否决方案

- **要点**：
  1. **卡片文案（卡 A）**：总结成功后，另发一次小的大模型调用。输入是标题、作者、平台加总结正文，输出用 JSON schema 约束为 `{headline, points[1..3]}`，按卡片契约落盘为 `llm_share_card.json`。文案语言跟总结正文一致。这一步失败只把错误记进日志和状态字段，不影响任务成功的终态。重新总结（resummarize）成功后重新生成；只重新校对、不重新总结时不动它。模型复用 `summary_model` 的配置。
  2. **出图与页面标签（卡 B）**：
     - 新增 `GET /og/{view_token}.png`：有 `llm_share_card.json` 就用 Pillow 渲染。缓存的 `og_card.png` 比 json 新就直接返回缓存，否则重新渲染并覆盖写入。没有 json 返回 404。
     - `transcript.html` 在有卡片文案时才输出 `twitter:card=summary_large_image`、`og:image`（基于 `web.base_url` 的绝对地址加版本号）、`og:image:width`、`og:image:height`、`twitter:image:alt`（取吸睛标题），并把 `og:description` 改成第一条要点。
     - Pillow 从开发依赖移到生产依赖。Dockerfile 用 apt 安装 `fonts-noto-cjk`；字体路径做成配置项，找不到字体时直接报错，不静默换字体。
  3. **卡片契约**（A 写、B 读，两张卡并行，契约先定死）：

     ```json
     {"version": 1, "headline": "≤30 个汉字或 ≤60 个英文字符",
      "points": ["每条 ≤40 个汉字", "..."], "generated_at": "ISO8601"}
     ```

     `points` 有 1 到 3 条。B 卡用这个形状造测试数据；A 卡要有测试锁住实际写出的文件内容就是这个形状。
  4. **版式**：画布 1200×630，深色底配品牌紫（#667eea）点缀。顶部一行写「平台 · 作者」（36px），吸睛标题加粗 64px，最多 2 行，超出加省略号。要点每条 36–40px，带序号，最多 2 行。底部写品牌域名（取自 `web.base_url` 的主机名）和「AI 总结」。
- **已否决**：
  - 在同一次总结调用里夹带输出卡片文案：会污染流式 Markdown 输出和篇幅预算控制（research.md 第 2 节），解析失败还会拖累总结本身。
  - 用视频封面做底图：没有任何平台持久化封面，抖音、B 站还有防盗链。
  - 用 Playwright 截图出图：生产镜像要带一个浏览器，太重。
  - 抓图请求进来时才现调大模型生成文案：X 的抓图程序几秒就超时。
  - 把字体文件提交进仓库：思源/Noto 中文字体单个文件 10MB 以上。

## 关键不变式

1. [实测] 没有 `llm_share_card.json` 的任务，页面输出与现在完全一致（不出现 `og:image` 和 `twitter:card`）。代码在 `transcript.html`，由卡 B 的视图测试锁住。
2. [实测] 卡片文案生成失败不改变任务终态，也不影响总结落盘。代码在卡 A 的调用点，由卡 A 用失败的模拟大模型调用写的测试锁住。
3. [实测] `og:image` 是绝对 https 地址，且带版本号。由卡 B 的视图测试锁住。
4. [实测] 重新总结会刷新卡片文案和版本号。由卡 A 的测试锁住。
5. [实测] 渲染出的图片是 1200×630 的 PNG，标题和要点超长时截断，不溢出画布。由卡 B 的渲染测试锁住。

## 待验证前提

1. [推断] 生产容器里 `fonts-noto-cjk` 的安装路径是 `/usr/share/fonts/opentype/noto/NotoSansCJK-Bold.ttc`。验证方式：卡 B 在镜像构建后执行 `fc-list | grep -i cjk`，把输出原文贴进报告。
2. [推断] CI 机器上有中文字体可供渲染测试使用。卡 B 先实测确认；没有的话不许跳过测试装绿，报告给主脑决定怎么处理。
3. [推断] X 能正常抓到 `/og/*.png`。合并部署后，用 `curl -A Twitterbot -I` 检查图片地址返回 200 和 `image/png`，再实际发一条推确认显示效果。

## 验收路径

1. 入口：部署后提交一个新的 YouTube 链接，等任务完成。
2. 步骤：打开 `/og/{token}.png` 看图；`curl -A Twitterbot` 抓分享页，检查新增的标签；把链接贴进 X 的发推框预览。
3. 预期：显示大图卡片，内容是吸睛标题、要点和来源；老任务的链接表现与现在一样。
