# Design: Web 端 PWA 化（可安装到桌面）
Generated by /plan-ceo-review on 2026-07-28，经 /plan-eng-review 加固于 2026-07-29
实施基线：从最新 main 单开 `feat/pwa-installable` 分支 + 独立 worktree | Mode: SELECTIVE EXPANSION
Repo: zlxlabs/VideoTranscriptAPI

## 问题定义

现有 Web 版（`/add_task_by_web` 提交任务、`/static/history.html` 任务历史）功能完整，
但每次使用要开浏览器、输地址、（在新设备上）输 Bearer Token。
目标：把网页版变成可安装 PWA，桌面/手机图标一键直达，独立窗口体验。

### 已确认的现状事实（评审期核查）

- Token 已持久化：app.js 用 localStorage `vta_bearer_token`（simpleEncrypt）保存，
  PWA 安装后 localStorage 保留，"每次输 token"主要发生在换设备/换浏览器/存储被清场景。
- 静态资源经 `NoCacheStaticFiles` 统一 `Cache-Control: no-cache`（app.py:35,316），
  Service Worker 缓存策略必须与此兼容，不能卡死页面更新。
- 仓库无现成 logo / 图标资产，无 manifest / SW / PWA 代码。
- 服务端为 FastAPI，静态文件 mount 在 `/static`，结果页在 `/view/{token}`。
- `/add_task_by_web`（views.py:742）匿名吐出 index.html，是 README 记载的产品入口。
- `GET /api/task/{id}` 对 failed 任务返回 **HTTP 200**，body 为
  `code=500, data.status='failed'`（tasks.py:507 普通 return；`http_code_for_status`
  算的是 body 里的 code 字段，不是 HTTP 状态）。前端轮询必须读 body 判定终态。
- `history.html` 不加载 app.js，无 `APIManager`（其 token 解密逻辑自带一份内联实现）。

## Vision

### 10x Check
用户的手机上刷到 B站/抖音视频，点分享直接选中本 PWA，链接自动填好，提交后去干别的，
任务完成弹系统通知。整个"看到视频到拿到转录"的路径从 5 步压到 2 步。
（注：本次交付覆盖"页面打开时"的通知；"关掉页面也能收"的完整闭环依赖 Phase 2
Web Push 后端，已登记 TODOS.md。）

### Platonic Ideal（12 个月）
PWA 成为本工具的主要入口：桌面固定在任务栏、手机在首屏、系统级分享接收、
任务完成推送触达。Web 端不再是一个"顺带提供的页面"，而是产品的门面。

## 实现路线（路线 A 最小可安装 PWA）

```
src/web/static/
  manifest.webmanifest   # 名称/图标/display/theme_color/shortcuts/share_target
  sw.js                  # Service Worker（决策表为纯函数，可 vitest）
  pwa.js                 # 注册 SW + 安装按钮 + iOS 引导（两页共用，DOM 胶水）
  js/pwa-share.js        # 分享预填纯函数（无 DOM 依赖，可 vitest）
  icons/                 # 192/512/maskable/apple-touch-icon 180（scripts/generate_pwa_icons.py 生成）
src/web/tests/           # vitest 用例（static 之外：不被 mount 公开 serve、不进生产镜像）
index.html / history.html # <link manifest> + 双 meta + pwa.js + 安装按钮
src/video_transcript_api/api/app.py  # +GET /sw.js 根路由（FileResponse 吐 static/sw.js，显式 Cache-Control: no-cache）
package.json / vitest.config.js      # 根目录 JS 工具链（node_modules 入 .gitignore）
```

manifest 关键取值（实施时不得随意改）：
- `start_url`: `/add_task_by_web`；`scope`: `/`（让 /view/ 结果页也留在 PWA 窗口内）；
  `id`: 固定为 `/add_task_by_web`（防止 manifest 更新被判定为新应用）；
  `display`: `standalone`（缺省 browser 会导致安装后仍在标签页打开，独立窗口落空）。
- `share_target`: `action: /add_task_by_web`、`method: GET`、
  params 同时声明 `url`/`title`/`text`（action 缺失则整个 share_target 被浏览器丢弃）。
- shortcuts 的 url 同样一律用 `/add_task_by_web` 与 `/static/history.html`。
- SW 作用域：`/static/sw.js` 天然只能控制 `/static/`。为让 scope 覆盖 `/`，
  在 FastAPI 增加 `GET /sw.js` 路由从根路径吐出同一文件（根路径脚本默认最大 scope 即 `/`，
  无需 Service-Worker-Allowed 头）。注册时一律用 `/sw.js`。
- iOS 不读 manifest 的 display：两页加双 meta（`mobile-web-app-capable` 标准 +
  `apple-mobile-web-app-capable` 旧版兼容）+ `apple-touch-icon`（180px）。

SW 策略（fetch 白名单制，scope 为 `/` 后会拦截同源所有请求，必须收紧）：
- `manifest.webmanifest`：network-first（文件极小，永远新鲜）。
- `icons/`：stale-while-revalidate。
- 导航请求：仅 index.html / history.html 两个入口页 network-first；
  其余导航（含 `/view/{token}` 结果页）一律 network-only、不写入 Cache Storage。
- `/api/*` 与其他一切请求：network-only，绝不落盘（Bearer 鉴权响应缓存即泄露）。
- 更新生命周期：缓存名带版本号（如 `vta-static-v1`），activate 时清理旧版本 cache；
  不做 skipWaiting 强制 reload；图标/manifest 变更必须 bump SW 版本号（写入实施清单）。
- `GET /sw.js` 根路由不得经过任何鉴权依赖（SW 脚本必须匿名可获取，否则注册失败）；
  验收：无痕窗口（无 token）能成功注册 SW。

## 平台兼容性边界（实施与验收都必须遵守）

- E1 安装按钮：`beforeinstallprompt` 仅 Chromium（桌面 Chrome/Edge + Android）。
  iOS Safari 永不触发：检测到 iOS 未安装时，按钮改显示"分享 → 添加到主屏幕"图文引导。
- E4 Share Target：仅 Android Chrome 生效，iOS 不支持 Web Share Target API
  （iOS 用户走复制链接兜底）。10x 分享路径只覆盖 Android。
- E4 分享载荷坑：B站/抖音 App 常把链接混在 `text` 参数（"【标题】 https://b23.tv/xxx"），
  `url` 参数经常为空。前端预填逻辑从 text 正则提取第一个 URL。
  验收标准：用 B站、抖音真实分享各验证一次。
- E4 固有边界（已接受并文档化）：GET 方式会把完整 title/text 拼进 URL
  （进服务器访问日志、受 URL 长度限制），个人工具接受该边界。
- E4 鉴权边界：新设备安装后 localStorage 无 token，分享进入预填了 URL 但提交会 401。
  预填后若无 token，聚焦高亮 token 输入框并提示"请先配置访问令牌"（app.js 已有此聚焦逻辑可复用）。
- E5 通知：iOS 需 ≥16.4 且必须从已安装的 PWA 内请求权限（Safari 标签页无效）。
  权限请求入口按"能力检测 → 不支持则隐藏"设计。
- E5 落地机制：
  - 复用 `APIManager.getTaskStatus(taskId)`（app.js:275），禁止重写 fetch/鉴权逻辑。
    **仅 index 页激活**（history.html 无 APIManager）；pwa.js 按能力检测降级。
  - 终态判定读 **body**：`data.status` 为 success/failed 即终态（failed 也是 HTTP 200）。
    success 弹通知；failed 静默停止。连续 5 次请求失败（网络/token 失效）停止并 console 警告。
  - 通知用页面级 Notification（页面上下文无 clients）：onclick 里
    `window.focus()` + `location` 跳 `/view/{view_token}`。
  - 权限必须由用户手势触发："提交成功后自动请求"在异步后不算手势，弃用；
    改为设置区显式"开启通知"按钮，点击时请求。
  - 内存态意味着页面刷新即丢失跟踪，属预期行为（简化版取舍）。
    实施注记（Codex R1-1 / R3-2）：实际落地已改为 localStorage 持久化 + 页面加载恢复——
    standalone 流程下提交后页面会离开 index，纯内存态永远无法送达通知（R1 P1 必修）。
  - 代码落在 pwa.js；app.js 提交成功分支 dispatch
    `CustomEvent('vta:task-submitted', {detail:{task_id, view_token}})`，pwa.js 监听。
  - standalone 模式下提交成功改为同窗口跳转（不再 `window.open('_blank')`，
    检测 `display-mode: standalone`；浏览器内既有行为不变）。
    实施注记（Codex R2-1）：实际落地为"standalone 取消自动跳转、原地提示 +
    同窗口链接"——跳转后 /view 无轮询能力，E5 通知会死；E5 简化版要求页面存活。

## 设计规格（/plan-design-review 7 维度评审产出）

- **安装按钮**：放页面顶部导航区（index.html:27 📋 任务历史 旁），两页一致；
  复用 styles.css 现有按钮类，📥 图标与产品 emoji 语言一致。
  状态机：可安装（beforeinstallprompt）→ 提示中 → 已安装（standalone 检测，隐藏）；
  用户 dismissed → 隐藏并冷却 7 天（localStorage 记录）。
  iOS：同位置改显示"分享 → 添加到主屏幕"图文引导，可关闭。
- **通知开关**：放"高级设置"区内。状态：未开启（显示"开启通知"）/
  granted（显示"通知已开启"）/ denied（永久隐藏入口 + 一次性提示去系统设置开）。
- **分享预填反馈**：成功填入后高亮提示"已从分享填入链接"；无 URL 时静默不提示。
- **品牌与启动画面**：`theme_color: #4f46e5`，`background_color: #ffffff`
  （白底启动画面 + 品牌色图标）；图标 brief：声波融入字幕行、扁平几何、
